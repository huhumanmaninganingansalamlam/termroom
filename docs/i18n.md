# Termroom localization

Termroom UI text is separated from templates and browser JavaScript so new
languages can be added without rewriting views.

```text
termroom/locales/
├─ en.json
└─ ko.json
```

Both files must contain the same key set. Automated tests enforce this and also
reject hard-coded Hangul in Python/templates/browser JavaScript.

## Locale resolution

1. `termroom_locale` cookie
2. `TERMROOM_LOCALE` from the runtime environment or Termroom `.env`
3. English default

Termroom intentionally does not auto-switch from the browser's `Accept-Language`.
`TERMROOM_LOCALE=en|ko` sets the operator-selected initial language. If it is not
configured, English is the default. The language selector writes the explicit
`termroom_locale` browser preference, which takes priority over the operator default.

## Adding a locale

1. Copy `termroom/locales/en.json` to the new locale file.
2. Translate values without changing keys/placeholders.
3. Add the locale to `SUPPORTED_LOCALES` in `termroom/i18n.py`.
4. Run the full test suite.

Templates use `t('key')`; browser scripts use the provided Termroom translation
dictionary. Do not duplicate display strings in JavaScript.

## Error localization

Errors that Termroom can identify carry a stable locale key and parameters. Stored
SSH errors use the `termroom-i18n:` envelope.

Unknown system/SSH errors should be shown safely rather than guessed or rewritten
into a misleading translation.
